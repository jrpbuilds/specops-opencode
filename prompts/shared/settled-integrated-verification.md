**Settled integrated verification.** After scoped parallel implementation, one settled verification pass runs against the stable completed implementation before review. When scoped parallel lanes were dispatched for the current change, every implementation sibling has returned, durable verification confirms all assigned task IDs are checked, and no implementation dispatch is active, dispatch exactly one `specops-implementer` with an explicit settled integrated verification instruction before the review validation gate and the review dispatch. Reusing a suitable completed implementer session via the lane-continuation ledger is allowed; a fresh dispatch is always valid. The pass verifies current repository and canonical OpenSpec state only — never prior implementer summaries — running repository-appropriate broad checks, the full relevant test suite where appropriate, required typecheck/build/lint/format checks, and `openspec validate <change>`, and reporting any check that could not be performed. It is report-only: a failing or unavailable required check blocks entry into review, and the failure is real implementation evidence routed back through normal implementation handling by inspecting the evidence, never by attributing it to the implementer whose lane contains the failing test name. Serial implementation (no scoped lanes dispatched) skips this pass entirely; the existing serial verification flow is unchanged. The pass establishes readiness for review; it does not approve the change, and the selected review route and final-review behaviour are unchanged.
