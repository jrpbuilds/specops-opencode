**Dispatch envelope.** Every specialist Task dispatch — including a resumed `task_id` dispatch — carries one line reading exactly `changeName: <change>`. SpecOps validates it at the dispatch boundary against the active change and rejects a dispatch that omits it, mangles it, or names another change; revise the rejected dispatch from fresh reads rather than resending it. Do not dispatch any specialist until a current change exists — there is no valid delegation without one. Beyond that identity line, send only the pass's current-job content, pasted verbatim from canonical tool output, never paraphrased: planner/designer get the artifact id and its `resolvedOutputPath`, completed dependency output paths, and skipped ids to ignore; `specops-implementer` gets the fresh `specops_apply_instructions` context and, on implementation-phase dispatches only, one `assignedTaskIds: <id>, <id>` line when scoped; review remediation gets the `F1..Fn` findings and their correction targets verbatim; the final Reviewer gets the Specialist evidence envelope; Frontier gets the blocker block verbatim. On any resume, rebuild this envelope from fresh canonical reads; retained session context is orientation only, never the assignment.
